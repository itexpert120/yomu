# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Yomu is a native Android EPUB reader (Kotlin + Jetpack Compose). The product intent is a polished, reader-first, tablet-optimized app. Its look is **Stack**, Open Reader's own design system (a grey desk, white sheets that slide up and stack, ink text, real covers; Instrument Sans; Material Symbols at weight 300), with Material 3 Expressive underneath only as behaviour (touch targets, springs, accessibility) — all applied through the `core/designsystem` layer. The locked Stack spec is summarised in the design-system section below. See `docs/` for the full product/design/architecture specs — `docs/README.md` is the entry point.

Current state: a **mature, feature-rich EPUB reader** — well past a minimal MVP. One `:app` module contains the custom design system, a Room-backed library (SAF import, Coil covers, search with recent searches, sort/views, multi-select bulk actions, and Stack's pile of books in progress with a play button), book details (two-pane on tablets, virtualized TOC with per-chapter read tracking, "mark to here" and collapsible volumes), and a Readium-backed reader with themes/fonts/brightness/extra-dim, in-reader TOC, **bookmarks**, **in-book full-text search**, **highlights** (colour palette, Highlight / Underline / Squiggly / Strikethrough styles, a note on each; notes show under their passage in Browse → Highlights; deleting a highlight or bookmark offers **Undo**, which restores the same row/id), **highlights & notes export / import** (Markdown / HTML / Open Reader JSON out through the share sheet, JSON in with a preview dialog, and the Calibre highlights inside an EPUB when it has some — from Book Details ⋯ and Browse → Highlights ⋯), **advanced typography** (line height, page margins, paragraph spacing, alignment), **dictionary word-lookup + TTS** (in the selection's language, with "Look up in English" when the book's language has no entry; a **Wikipedia** tab, and short phrases open on it; **Translate** hands the text to the device's translation app; **Search in book**), **Copy with citation** and other apps' text actions (`ACTION_PROCESS_TEXT`: Translate, dictionaries) in the selection menu, footnote popups, and saved custom reader themes. Library **tabs**: All · Reading · To read · Finished (+ On hold / Dropped while non-empty) and the user's own **collections** (a book can be in many), as a swipeable pager under a strip of word tabs (no counts) whose ink line follows the pager 1:1, on a white sheet that lifts over the pile; the last tab, a user tab order, and hidden built-in tabs are remembered per device (Library tabs sheet via the strip's "+ Add"). Every book shows one **shelf status** (To read / Reading / Finished from progress, or a manual On hold / Dropped that always wins, Statistics included); books get a manual status and collections from multi-select **Organize** or Book details; collections and statuses sync (`collection/<id>`, `shelf/<sha>`). Also built: a **reading-statistics** dashboard (a calendar Week / Month figure + chart that pages back through past weeks and months, streak/metric tiles, per-book "Time by book" lifetime totals, session history), **external "Open with"/share** EPUB import, and **launcher quick actions** (long-press the app icon: static Search library / Import books / Statistics in `res/xml/shortcuts.xml`, and a dynamic "Continue <book>" for the front of the pile with its cover as an adaptive icon, republished only when that book changes and removed when there is none — `app/shortcuts/`; MainActivity hands the intent to `ExternalOpenViewModel`, and `YomuNavHost` closes what is open over the top-level screens, then the shell selects Statistics or the library opens search / the import picker via `LibraryEntryAction`; Continue opens the reader like an external open). **Hilt, Room, DataStore, Navigation Compose, Coil, Readium and foliate-js are all present and wired.** (Home-screen Glance widgets were removed.)

Network features: the dictionary lookup (Free Dictionary API), Wikipedia summaries (`data/encyclopedia/WikipediaRepository`, only once the look-up sheet's Wikipedia tab opens; generic `OpenReader/<version> (Android)` user agent; the thumbnail is fetched by the same client since Coil has no network fetcher here), Google Fonts installs (`data/fonts/FontRepository`, TrueType files under the same generic user agent so Android can preview them in the font chips; fonts installed as woff2 by earlier versions are fetched again once), and **account-less sync** (a 12-word BIP39 phrase → end-to-end-encrypted records on a Convex backend in `backend/convex/`; see `docs/sync.md`). Sync runs only while the app is in the foreground (`ProcessLifecycleOwner` in `SyncRepository`): on background it stages + pushes pending changes (bounded wait), then stops and closes the connection; it resumes on return. Everything else is offline. Remaining gaps are later-phase roadmap items (e.g. OPDS catalogs, non-EPUB formats like PDF/audiobook) — see `docs/roadmap.md`. The `docs/` describe the product/design intent and are kept current — each doc has an "Implementation status (current)" note, and `docs/roadmap.md` (Phases 0–12) is the authoritative done-vs-pending source. **Keep this CLAUDE.md in sync with the code as features land.**

## Commands

Use the Gradle wrapper. On this Windows/PowerShell environment use `./gradlew` (Bash tool) or `.\gradlew.bat` (PowerShell).

```bash
./gradlew assembleDebug          # build debug APK
./gradlew installDebug           # build + install on connected device/emulator
./gradlew test                   # JVM unit tests (src/test)
./gradlew connectedAndroidTest   # instrumented tests (src/androidTest, needs device)
./gradlew lint                   # Android lint
./gradlew :app:compileDebugKotlin  # fast compile-only check

# Baseline Profile (checked in under app/src/release/generated/baselineProfiles) + macrobenchmarks.
# Both install release-type builds under the SAME app id, wiping that device's library.
./gradlew :app:generateBaselineProfile -Pandroid.testInstrumentationRunnerArguments.androidx.benchmark.suppressErrors=EMULATOR
./gradlew :benchmark:connectedBenchmarkReleaseAndroidTest "-Pandroid.testInstrumentationRunnerArguments.tests_regex=.*LibraryBenchmark.*" -Pandroid.testInstrumentationRunnerArguments.androidx.benchmark.suppressErrors=EMULATOR

# run a single JVM unit test
./gradlew test --tests "com.itexpert120.yomu.ExampleUnitTest"
./gradlew test --tests "com.itexpert120.yomu.ExampleUnitTest.addition_isCorrect"
```

There is no separate "run tests" vs "lint" toolchain beyond Gradle. All external dependency versions live in `gradle/libs.versions.toml` (version catalog) — add dependencies there, referenced as `libs.*`, never inline in `build.gradle.kts`.

Toolchain: Gradle 9.9.2, AGP 9.5.2, Kotlin 2.4.21, Navigation Compose 2.10.2 (its default predictive-back transitions are overridden in `YomuNavHost`), Readium 3.4.0, Compose BOM (stable) 2026.11.01 → material3 1.5.0 / Compose 1.13.0 (needs `compileSdkMinor = 1`, i.e. platform android-37.1), **Java 17** (+ core-library desugaring), KSP. `compileSdk 37 / minSdk 26 / targetSdk 37` (26 is required by the Convex Android client). DI is Hilt (with `hilt { enableAggregatingTask = false }` — a workaround for Kotlin 2.4.0 metadata vs Hilt's javac aggregator); Room uses KSP with schema export to `app/schemas`. The app theme parent is `Theme.AppCompat.DayNight.NoActionBar` so it can host the Readium navigator Fragment.

### Design system: Stack through `core/designsystem`
`YomuDesignTheme` wraps the app in `MaterialExpressiveTheme` (expressive `MotionScheme`, full M3E shape scale, baseline + explicitly-weighted `*Emphasized` type). Colour and type come from `MaterialTheme.colorScheme/typography` (the old `YomuTheme.colors/type` bridge was removed); `YomuTheme.space/radius` are real tokens, and `YomuReadingTokens` holds the only values Material has no role for (`YomuTheme.reading` highlight palette per light/dark, `YomuReadingTokens.Mono` / `ReaderSample` text styles).
- **Colour**: Stack has no app accent — colour comes from covers and reading themes only. `core/designsystem/StackTokens.kt` holds `StackColors` (desk, sheet, raised, ink, onInk, body, muted, faint, rule, track, danger, plus `elevated` — floating sheets/dialogs, a step above the sheet in the dark — and `lifted` — a segmented chip or chosen tile on a raised track; `menu` = raised in the dark, with a hairline) for Light / Dark / Black (dark elevation is lightness: desk < sheet < elevated < raised < lifted, pinned by `YomuThemeTest`; `YomuBottomSheet` and `YomuDialog` run their content in `YomuFloatingSurface`, where `sheet`/`surface` = elevated) (`YomuThemeMode.Oled` = pure black), exposed as `YomuTheme.stack` and mapped onto Material's roles (background = desk, surface = sheet, surfaceContainer* = raised, primary = ink, onSurfaceVariant = muted, outline = track, outlineVariant = rule, error = danger; no tonal elevation). `YomuThemeTest` checks every text token's contrast on sheet and desk. Settings → Appearance keeps only Light / Dark / Auto and Pure black (the stored `AccentSelection`/`ColorStyle` fields are unused). Type is **Instrument Sans** (bundled variable font, `res/font/instrument_sans.ttf`, SIL OFL) on `StackType` (Display 32, Figure 44 condensed, Title 26, Heading 15, Body 15, BodySmall 14.5, Label 13, Caption 12 — also mapped onto `MaterialTheme.typography`). Corners: covers 4 (`Modifier.stackCoverShadow()` is the one static cover shadow), rows 16, cards 24, sheets from the display: `rememberDisplayCornerRadii()` (`YomuDisplayCorners.kt`, API 31+ `RoundedCorner`, re-read on every window layout — rotation, folding, resizing; null on square displays, older APIs and in previews) drives `yomuSheetCorner()` — a phone sheet's top corners (bottom sheets, the book sheet and the reader rising from it, `rememberBookSheetCorner`) echo the display's bottom corners, 32dp where it reports none, never below 24 — and `yomuConcentricCorner(gap, minimum)` for surfaces floating near an edge (the floating notice: display radius less its 16dp gap, at least 16); the tablet side sheet's leading corners are 32 or the display's, whichever is rounder. The reader's sheets run in a Stack theme matched to the reading page (`ReaderRoute`), so a Night page gets dark sheets.

The rail lies on the desk (80dp, items from the top; centred on a landscape phone). The library pile fills empty slots (one or two books) with raised cover-shaped blanks, shows the chapter you are in (from the already-indexed contents) under its figure, and turns over as a loop: the front cover follows the finger 1:1, the covers behind move up with it, and release commits by distance or velocity (`pileSettleTarget`). Library layouts follow the boards: phone, portrait tablet (larger pile, info at the far edge) and landscape column (info beside the pile); on tablets the shelf sheet stands 16dp off the rail and the grid's automatic columns keep covers about board size for any width. The splash holds until the library has its books (`LocalYomuContentReady`, ≤900 ms), so it hands over to the real first frame.
- Still custom by necessity: the HSV `YomuColorPicker`, the scroll indicator, EPUB canvas. Adaptive layout follows the M3 breakpoints: `YomuWidthClass` (Compact <600 / Medium / Expanded ≥840 / Large ≥1200, `margin` 16→24dp), `YomuTwoPane` (24dp margins + spacer; 50/50 at medium, fixed 360/412dp leading pane from expanded), `YomuReadableMaxWidth` (720dp default for `YomuScreenScaffold` forms/prose) vs `YomuContentMaxWidth` (1040dp for grids/dashboards). Book Details two-pane uses contained panes below the app bar (the Read/Resume button docks under the details pane instead of floating over the TOC) and reveals the bar title only once the in-pane title scrolls away; Stats splits only from expanded. The module opts into `ExperimentalMaterial3ExpressiveApi` globally (`app/build.gradle.kts`) — most M3E components are stable as of material3 1.5.0, but `LoadingIndicator` and `MaterialShapes` still need it.
- **Icons**: every app icon is `core/designsystem/icons/StackIcons` — Material Symbols Outlined at weight 300 as generated `ImageVector`s (no `material-icons-extended` dependency). `*Filled` (FILL 1, weight 400) only for the active nav item and the play/resume button; `BookmarkFilled` (FILL 1, weight 300) is the bookmark toggle's on-state. Add an icon by appending it to `tools/stack-icons/generate_stack_icons.py` and running it with `--fetch` (SVGs go to a scratch dir outside the repo).
- The design system package must not depend on `feature/*`.

- **Motion/performance rules**: no raw `tween`/`spring` in feature code — geometry uses `MaterialTheme.motionScheme` spatial specs, opacity/colour the effects specs, appear/disappear the `YomuMotion` helpers. Animated values are read in the draw/layout phase (`graphicsLayer { }`, `offset { }`, draw lambdas), not in composition, so animations hold the display's native refresh rate. `YomuBottomSheet` is a side sheet (≤420dp) from 600dp width; confirmations stay centred `YomuDialog`s.

### Theme ↔ system bars
`MainActivity` owns the window insets controller and flips status/nav bar icon appearance on theme-mode change so bar icons stay legible. It also calls `preferNativeRefreshRate()` (`app/NativeRefreshRate.kt`) so the window requests the display's fastest mode (90/120/144 Hz) at the current resolution, re-picked on every display change while started (Samsung hides its high-rate modes during battery saver). The **reader** additionally takes over the system bars while open (`ReaderScreen`): it hides both bars for full-screen reading, colours them to the reading theme, and restores them on exit.

### Reader engine boundary
**v2 (branch `v2-native`): foliate-js is the default engine; Readium is the fallback.** The bound `ReaderEngine` is `data/reader/SwitchingReaderEngine`, which forwards to `data/reader/foliate/FoliateReaderEngine` unless `ReaderEngineChoice` (About → Diagnostics → "Use previous reading engine", device-local) picks `ReadiumReaderEngine`. The foliate side lives in the `:reader-engine` Gradle module: `reader/web/FoliateReader` hosts vendored foliate-js (MIT, EPUB-only subset in `reader-engine/src/main/assets/foliate/`, our glue in `yomu-reader.js`) in one WebView on a single local origin (book files served one at a time from the EPUB, CSP blocks book scripts, no network). Reading fonts load from that origin by absolute URL (`fontURL` in yomu-reader.js: chapter documents are blob: URLs, against which a root-relative path never resolves — every font used to fall back to serif): bundled ones from `/assets/fonts/`, an installed one at `/userfonts/<its file name>`, only the chosen font's files (`data/reader/foliate/FoliateFont`; a per-font URL, so switching fonts never draws the old one from cache). Page turns are foliate's own (finger-following swipe + slide; off when system animations are); taps in the outer thirds (also beside the text column) turn left/right in the book's direction. Paged, foliate's top/bottom `margin` is 16px (the screen's insets do the rest); a landscape window at least 840px and 44em wide shows a two-page spread with a plain gutter, no line (in a spread a column is capped at half the page so narrow margins can't drop it to one; `configureColumns` sets the column count before `max-inline-size`, the attribute that re-lays out, so a setting that turns the spread on applies without a resize) (`ReaderSettings.twoPageSpread`, device-local, default on; "Two pages in landscape" in Reading settings and defaults), and `relocate` counts pages, not screens. A book-like page curl that follows the finger is planned for tablets/foldables in landscape; the earlier native snapshot-slide turn and chapter stand-in were removed (see git history: `FoliatePageTurns`, `yomu-standin.js`). `FoliateReaderEngine` writes the same Readium-shaped locator JSON (href + progression, plus `locations.cfi`) and keys chapters by Readium's TOC (`ReadiumReaderEngine.publicationCache`), so positions, bookmarks and read marks work across both engines. Opening is preloaded: `warmUp()` builds a warm reader page (WebView + scripts loaded, on a `MutableContextWrapper` re-parented to the Activity when adopted) and `prepare()` reads the book ahead and loads it into that page, so a tap only places and paints the page (Resume tap → ready ~0.5 s vs Readium ~1.0–1.4 s on the emulator). The text-selection menu is the reader's own (`reader/web/SelectionMenu` wraps Chromium's ActionMode in a `WebView` subclass; the page's `yomuSelection()` gives text + CFI; after its own items — Copy, Highlight, Look up, Search in book, Search web, Read aloud, Share, Copy with citation — it lists other apps' `ACTION_PROCESS_TEXT` actions, launched read-only with the selected text, which needs the manifest's `<queries>`), and highlights draw through foliate's overlayer (`yomuSetHighlights`; taps come back as `highlight-tap`). Highlights made under foliate carry a CFI; those made under Readium carry only their quoted text (`text.before/highlight/after`), which the page finds (`findText`) when their chapter loads — and a locator without a CFI but with quoted text (Readium bookmarks/highlights, positions synced from a Readium device) is navigated to the same way, falling back to its progression. In-book search skips foliate's own (slow) search: `reader/web/SearchText` scans the raw chapter files on 4 threads in growing blocks and the page (`yomuSearch`) opens and matches only the chapters that can match, with the same folding (no case/diacritics, collapsed whitespace); hits carry the CFI and are underlined with `yomuSetSearchHits` (≤150 hits like Readium; on the 1,469-section test book a common name takes ~0.6 s, a word that isn't there ~3.3 s on the emulator). Footnote references (epub:type/role noteref, or a superscript link that isn't a back-link, as foliate's footnotes.js decides) open the note's HTML in the footnote popup instead of navigating. Paged pages scroll **edge to edge**: in `paginator.js` (marked "Open Reader:") the scrolling container spans the whole width and the room beside the text box (`#text-box`, the old container) becomes column gaps, so columns keep their width (same line breaks and page counts), a single page keeps its margins exactly and a spread's gutter widens by what its outer margins give up; a touch moving under 8px isn't a drag. **Section crossings are one slide:** the adjacent section is laid out ahead in a hidden second `foliate-paginator` (`#yomu-preview`, same settings, box and highlights) — the next one near a section's last pages, the previous one (at its end) near its first; its offset is bound to the outgoing scroll position (`followTurn`), so it follows a tap's slide or the finger in from the same side, covers the page while foliate loads that section underneath, and steps aside once it has settled (`followCrossing`). `next`/`prev`/`snap` are wrapped (`guardTurns`) so a crossing waits up to 1.5 s for the preview (the outgoing page stays put); past that, the older fallback slides the section in once loaded. RTL turns the other way; animations off is a cut to the preview; settings or size changes drop the preview. Page list: `relocate` carries `pageLabel` (the printed page on screen, "112–113" across a spread) → `ReaderLocator.pageLabel`; the list itself goes over once as `page-list` → `ReaderSession.pageList` (`ReaderPageTarget`; Readium supplies the list from `publication.pageList` but no current label). A followed link reports `link-jump` → `ReaderSession.linkJumps` (Readium: `shouldFollowInternalLink`). A tap on a picture outside the page-turn thirds, or a long press anywhere, sends its bytes as `image` (SVG drawn to PNG) → `ReaderSession.images` (foliate only). `yomuSelection()` adds `language` (nearest `lang`/`xml:lang`, else the book's, primary subtag; Readium: the book's). Highlights draw in their `HighlightStyle` (Overlayer `highlight/underline/squiggly/strikethrough`, a dot when they carry a note; Readium: `Underline` plus our own squiggly/strikethrough `HtmlDecorationTemplate`s in `ReadiumHighlightStyles`). Debug builds enable WebView remote debugging (chrome://inspect). **Pictures on dark pages** (`ReaderSettings.adaptPictures`, "Adapt pictures to dark pages", default on, synced, in both chrome-toggle UIs): the page measures each picture once at its own size (≤256 px: chroma, near-black/near-white shares, light corners, size in text lines, markup hints) and asks the app over the JS bridge (`YomuHost.pictureTone` → pure `reader/web/PictureTone`, unit-tested on Love Unseen fixtures): never colour or a marked illustration/cover; a picture a few lines small that's colourless is line art when marked (a decoration class, `alt=""`) or light-cornered and ≥0.6 two-tone; bigger ones only when ≥0.96 two-tone. Line art gets `data-yomu-ink` and the injected CSS takes it onto the page's own colour: inverted and screened on a dark page, multiplied on a light one (so no box on sepia or a custom colour); the blend works because everything between the picture and `html` is transparent. Decisions are cached per EPUB path (`picturePathsOf` reads the section's own markup), so a section is marked in its `load` handler before it shows, the crossing preview decides ahead, and undecided pictures stay hidden (`data-yomu-pending`) until decided; the first page (and a crossing's swap) waits ≤100 ms for them. Debug builds log each decision to the console (`?debug=1`). **Nothing settles after the first frame:** highlights are sent with the open (`yomuSetHighlights` waits for the book) so the first page draws them; a theme or alignment change applies in one task (fonts are awaited only when the font changes). Scroll mode (`flow="scrolled"`, one chapter at a time): pulling on past a chapter's end or start drags the chapter with growing resistance (a badge with an arrow, kept clear of bars and cutout via `yomuSetSafeArea`, fills once release will act at 140 CSS px of finger travel); letting go there carries the chapter out the way it was pulled and brings the adjacent section in from the same side — the page navigates itself and reports `continue` first (forward counts as reading through, via `ReadingPosition.expectSequentialCrossing`); scroll progress reaches 100% at a chapter's end; the page draws its own fading scrollbar (`showScrollbar`), as the chapter scrolls inside foliate's closed shadow root. Session hooks: `onForegroundResumed()` probes the page (`yomuAlive`); a page that doesn't answer within 4 s has its renderer terminated (rebuilt like a crash, at the same CFI), one that lost its chapter is sent back to it; `portableLocator()` adds the text at the top of the screen (`yomuPortable`: raw `text.before/highlight/after`) to the CFI locator so Readium can anchor on it. `:reader-engine` also holds the parked native-layout prototype (`reader/epub`, `text`, `layout`, `ui`); debug-only `prototype/*PrototypeActivity` launch either directly. The rest of this section describes the Readium engine.

The root host and the tab host run backs as seekable transitions (`BackMotion`: their pop specs keep the leaving page, a 450 ms linear clock, `YomuMotion.BackSlideMillis`); while a finger drags the page follows it 1:1, on release it continues on the default spatial spring from the release point at the finger's speed and lands as the transition ends, a cancel retraces, and a tap plays the same commit from rest. The book sheet slides down the same way (`BookSheetFrame`, from `BookSheetHold` when a drag closed it: the sheet hands its position to navigation instead of animating itself, so it never goes away and comes back). Every in-app back (`popWhenSettled` in `YomuNavHost`) pops now or, while the page is still opening, once it has settled — never dropped. Sheets follow the swipe on their own motion (`YomuSheetBackHandler`); custom dialog surfaces (`YomuDialog`, cover viewer) via `YomuBackPreviewHandler` + `Modifier.yomuBackPreview` (they slide, never shrink). Chapter changes reveal the new chapter with a directional rise/settle (`ReaderScreen` `revealShift`) and leave the chrome as-is (only the initial open forces it visible); paged tap-turns use Readium's animated pagination under Readium (`goForward(animated = …)`) and foliate's own slide under foliate, both off when system animations are disabled. The reader footer is composed from the start (invisible until the page is ready) so the book's first layout already reserves its height — measuring it after the open resized the page under the reader.

## Conventions

- Each feature follows a **Route (stateful, `hiltViewModel()`) → Screen (stateless, `On*` callbacks)** split; the `Screen` is preview-driven.
- Compose state flows down (immutable UI-state data classes), events flow up (explicitly named `On*` events). Collect ViewModel/repository flows with `collectAsStateWithLifecycle()`, and build heavy UI state (sorting, TOC models) off main with `flowOn(Dispatchers.Default)`. Keep composables stateless except for small ephemeral UI state.
- **The reader is the exception to `On*` callbacks:** every reader event is an explicitly named member of one sealed `ReaderAction` (`feature/reader/ReaderAction.kt`, e.g. `ReaderAction.OpenSearch`) raised through a single `ReaderScreen(state, onAction)`. `ReaderViewModel.onAction` runs the pure, unit-tested `reduceChrome` (menu/sheet exclusivity) and forwards book work to `ReadingExperience` via `toExperienceAction()`; `ReaderRoute` handles `Back`. Add a reader event as a new `ReaderAction`, not a new callback (leaf sheets still take named callbacks). The reading-session lifecycle (resume/pause → reading time) is owned by `ReaderRoute` (`LifecycleResumeEffect` on the destination), not the screen.
- Do not pass repositories into composables, and do not run import/database/DataStore/Readium work from composables.
- Name composables by product role, not the widget they render.
- The Book Details TOC must stay a `LazyColumn` (can be thousands of entries) **with no item key** — chapter hrefs can legitimately repeat and a keyed list would crash.
- Comment only non-obvious behavior.
- Use `@Preview` composables for design iteration; the `app/devgallery` gallery exists to validate design primitives in isolation.

## Related projects (local siblings — reference material, not dependencies)

Two other repos live next to Yomu on this machine. Neither is built or imported by Yomu, but both are high-value references — especially for Yomu's genuinely-missing features (bookmarks, in-book search). ### `C:\Users\itexp\kotlin-toolkit\test-app` — the Readium reference app (the engine Yomu sits on)
The official **Readium Kotlin Toolkit** monorepo and its demo app (`org.readium.r2.testapp`, versioned in lockstep at **3.3.0**; Yomu now targets Readium **3.4.0**, so check the 3.3→3.4 changelog when porting). It is the canonical, un-abstracted reference for the library under Yomu's reader. Style is the *opposite* of Yomu: classic **Views/Fragments/RecyclerView + Material**, hand-rolled DI (no Hilt), and Readium types used directly everywhere. Exercises the whole toolkit (EPUB / PDF via PDFium / audiobook via ExoPlayer+media3 / image-DiViNa / OPDS / LCP DRM / TTS / search / bookmarks / highlights / TOC / preferences).

Best copy-from source for **Yomu's two missing features**:
- **Bookmarks** — Room entity stores the Readium `Locator` as JSON (`locations` + `text`); spine index via `publication.readingOrder.indexOfFirstWithHref(href)`; idempotency via a unique index + `OnConflictStrategy.IGNORE`; `BookmarksFragment` lists then returns a `Locator` → `navigator.go(locator)`.
- **In-book search** — `publication.search(query)` → `SearchIterator`, paged lazily with an AndroidX Paging 3 `SearchPagingSource`; hits rendered live in-text as `Decoration.Style.Underline` via `DecorableNavigator.applyDecorations(list, group)`.
- **Highlights** (Yomu's are built, but this is the textbook version) — text-selection `ActionMode` → `SelectableNavigator.currentSelection()` → Room `Highlight` → `Decoration` (group `"highlights"`); `Decoration.extras` round-trips the DB id so `onDecorationActivated` can look the row back up for tap-to-edit.
- Also worth knowing: multi-format navigator selection by `Publication.Profile`; custom font declaration at navigator-config time (same mechanism Yomu uses); the `createDummyFactory()` process-death guard — the same navigator-restoration crash class Yomu fixed in 07ac465.
- **Caveat for porting:** the test-app reaches into Readium from its ViewModels/Fragments. A Yomu port must thread these through `core/reader` (e.g. add `search()` / `applyDecorations()` to `ReaderSession`), not import Readium in `feature/reader`.

### `C:\Users\itexp\vaachak` — sibling indie Compose EPUB reader
Another single-module native EPUB reader (`io.github.piyushdaiya.vaachak`, v2.0.1) on the **same core stack** (Compose, Hilt, Room, DataStore, Coil, Readium) but **older versions**: Kotlin 2.0.21, AGP 8.11.1, Compose BOM 2024.05, **Readium 3.1.2** (vs Yomu's 3.4.0 — APIs are not always drop-in), minSdk 30, Room v9. It ships several things Yomu lists as pending, plus features Yomu has no plans for — so it's the most useful *feature* reference, but **not** an architecture reference.

- **Built features to study:** in-book search (Readium `SearchService`), highlights + page bookmarks (unified into one Room `HighlightEntity` discriminated by a string `tag`; bookmark identity by href + `abs(progression delta) < 0.01`), flattened TOC overlay, fragment-in-Compose with a `FragmentLifecycleCallbacks` re-apply-decorations-on-resume pattern.
- **Beyond Yomu's scope:** an **AI assistant** — Google **Gemini** (`gemini-2.5-flash`) for explain / spoiler-free character ID / chapter recap / session "recall", plus **Cloudflare Workers AI** for text→image (both BYO-key in DataStore); an **offline dictionary** — embedded `dictionary.json` (~20MB) + `inflections.json` lemma map + a from-scratch `StarDictParser` (`.ifo/.idx/.dict.dz`, 32/64-bit offsets, gzip via commons-compress); **catalog acquisition** — OPDS 1.x/2.0 (`readium-opds`) + **Gutendex** (Project Gutenberg) browse + in-app download; **accessibility fonts** (OpenDyslexic, iA Writer Duospace, accessible DfA) and a first-class **E-Ink** theme mode with a contrast slider.
- **Architectural contrasts (why not to copy its structure):** stock **Material3** with a single global `isEink` boolean instead of a design system; **no Readium boundary** (Readium types leak into Compose UI + ViewModels); **no `NavHost`** — a monolithic `MainActivity` holds all navigation as Compose state; the data layer even depends on a `ui` class (`LibraryRepository` → `ui.reader.ReadiumManager`); a ~550-line god `ReaderViewModel`.
- **Do not copy (security):** `app/build.gradle.kts` hardcodes the release **keystore password in plaintext** in the signing config; user AI secrets are stored unencrypted in DataStore; OPDS offers a trust-all-TLS path. Treat vaachak as a feature blueprint only.
