# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Yomu is a native Android EPUB reader (Kotlin + Jetpack Compose). The product intent is a polished, reader-first, tablet-optimized app built on **Material 3 Expressive** (M3E) — expressive shapes, springs, emphasized type, and seeded colour themes, applied through the `core/designsystem` layer. See `docs/` for the full product/design/architecture specs — `docs/README.md` is the entry point.

Current state: a **mature, feature-rich EPUB reader** — well past a minimal MVP. One `:app` module contains the custom design system, a Room-backed library (SAF import, Coil covers, search/sort/group, multi-select bulk actions, continue-reading hero), book details (two-pane on tablets, virtualized TOC with per-chapter read tracking and "mark to here"), and a Readium-backed reader with themes/fonts/brightness/extra-dim, in-reader TOC, **bookmarks**, **in-book full-text search**, **highlights** (with an optional colour palette), **advanced typography** (line height, page margins, paragraph spacing, alignment), **dictionary word-lookup + TTS**, footnote popups, and saved custom reader themes. Library **tabs**: All · Reading · To read · Finished (+ On hold / Dropped while non-empty) and the user's own **collections** (a book can be in many), as a swipeable pager under a pill tab strip whose indicator follows the pager 1:1; the last tab, a user tab order, and hidden built-in tabs are remembered per device (Library tabs sheet via the strip's "+ Add"). Every book shows one **shelf status** (To read / Reading / Finished from progress, or a manual On hold / Dropped that always wins, Statistics included); books get a manual status and collections from multi-select **Organize** or Book details; collections and statuses sync (`collection/<id>`, `shelf/<sha>`). Also built: a **reading-statistics** dashboard (hero total, streak/metric tiles, per-book "Time by book" lifetime totals, session history) and **external "Open with"/share** EPUB import. **Hilt, Room, DataStore, Navigation Compose, Coil, MaterialKolor, and Readium are all present and wired.** (Home-screen Glance widgets were removed.)

Network features: the dictionary lookup (Free Dictionary API), Google Fonts installs, and **account-less sync** (a 12-word BIP39 phrase → end-to-end-encrypted records on a Convex backend in `backend/convex/`; see `docs/sync.md`). Sync runs only while the app is in the foreground (`ProcessLifecycleOwner` in `SyncRepository`): on background it stages + pushes pending changes (bounded wait), then stops and closes the connection; it resumes on return. Everything else is offline. Remaining gaps are later-phase roadmap items (e.g. OPDS catalogs, non-EPUB formats like PDF/audiobook) — see `docs/roadmap.md`. The `docs/` describe the product/design intent and are kept current — each doc has an "Implementation status (current)" note, and `docs/roadmap.md` (Phases 0–12) is the authoritative done-vs-pending source. **Keep this CLAUDE.md in sync with the code as features land.**

## Commands

Use the Gradle wrapper. On this Windows/PowerShell environment use `./gradlew` (Bash tool) or `.\gradlew.bat` (PowerShell).

```bash
./gradlew assembleDebug          # build debug APK
./gradlew installDebug           # build + install on connected device/emulator
./gradlew test                   # JVM unit tests (src/test)
./gradlew connectedAndroidTest   # instrumented tests (src/androidTest, needs device)
./gradlew lint                   # Android lint
./gradlew :app:compileDebugKotlin  # fast compile-only check

# Baseline Profile (checked in under app/src/release/generated/baselineProfiles) + macrobenchmarks.
# Both install release-type builds under the SAME app id, wiping that device's library.
./gradlew :app:generateBaselineProfile -Pandroid.testInstrumentationRunnerArguments.androidx.benchmark.suppressErrors=EMULATOR
./gradlew :benchmark:connectedBenchmarkReleaseAndroidTest "-Pandroid.testInstrumentationRunnerArguments.tests_regex=.*LibraryBenchmark.*" -Pandroid.testInstrumentationRunnerArguments.androidx.benchmark.suppressErrors=EMULATOR

# run a single JVM unit test
./gradlew test --tests "com.itexpert120.yomu.ExampleUnitTest"
./gradlew test --tests "com.itexpert120.yomu.ExampleUnitTest.addition_isCorrect"
```

There is no separate "run tests" vs "lint" toolchain beyond Gradle. All external dependency versions live in `gradle/libs.versions.toml` (version catalog) — add dependencies there, referenced as `libs.*`, never inline in `build.gradle.kts`.

Toolchain: Gradle 9.9.2, AGP 9.5.2, Kotlin 2.4.21, Navigation Compose 2.10.2 (its default predictive-back transitions are overridden in `YomuNavHost`), Readium 3.4.0, Compose BOM (stable) 2026.11.01 → material3 1.5.0 / Compose 1.13.0 (needs `compileSdkMinor = 1`, i.e. platform android-37.1), **Java 17** (+ core-library desugaring), KSP. `compileSdk 37 / minSdk 26 / targetSdk 37` (26 is required by the Convex Android client). DI is Hilt (with `hilt { enableAggregatingTask = false }` — a workaround for Kotlin 2.4.0 metadata vs Hilt's javac aggregator); Room uses KSP with schema export to `app/schemas`. The app theme parent is `Theme.AppCompat.DayNight.NoActionBar` so it can host the Readium navigator Fragment.

### Design system: Material 3 Expressive through `core/designsystem`
`YomuDesignTheme` wraps the app in `MaterialExpressiveTheme` (expressive `MotionScheme`, full M3E shape scale, baseline + explicitly-weighted `*Emphasized` type). Colour and type come from `MaterialTheme.colorScheme/typography` (the old `YomuTheme.colors/type` bridge was removed); `YomuTheme.space/radius` are real tokens, and `YomuReadingTokens` holds the only values Material has no role for (`YomuTheme.reading` highlight palette per light/dark, `YomuReadingTokens.Mono` / `ReaderSample` text styles).
- **Colour**: `AccentSelection` (`Wallpaper` | `Preset(AccentColor)` | `Custom(argb)`) + `ColorStyle` (Balanced/Vibrant/Expressive/Neutral — Neutral is seed-tinted near-greyscale; a stored "Monochrome" migrates to it) are persisted in DataStore and expanded to full tonal schemes with **MaterialKolor** (`dynamicColorScheme`, `SPEC_2025`) in `yomuColorScheme`. Default is the wallpaper palette on Android 12+, else the Ocean preset. OLED applies `toOled()` on top of any dark scheme. Picker lives in Settings → Appearance.
- **Primitives** (delegate to real M3E components): `YomuConnectedChoiceGroup` (connected ToggleButtons — use instead of segmented buttons; give every option an `icon`, which pops via `Modifier.yomuSelectionPop` on selection; `iconOnTop` stacks icon over label for 4+ options), `YomuSelectableChip` (multi-select chip: icon↔check swap, pill→square morph, all draw-phase — e.g. reader footer/screen toggles), `YomuFloatingToolbar`/`YomuToolbarAction` (selection + reader actions; never alongside the nav bar — `YomuTopLevelNavigation(barVisible)` hides it), `YomuSettingRow` (`SegmentedListItem` with `YomuSettingPosition`), `YomuSettingContainer` (segmented container for sliders/pickers), `YomuSettingGroup` (primary emphasized header, no card nesting), `YomuSectionLabel`, `YomuValueChip`, `YomuTogglePill` (switch with check/close thumb + haptics), `YomuLoadingIndicator`/`YomuLoadingState` (morphing loading indicator for short waits), `YomuProgressBar` (wavy for hero progress), `YomuExtendedFloatingActionButton` (small extended FAB), `YomuScreenHeader`/`YomuScreenScaffold` (`LargeFlexibleTopAppBar`, IME-aware scrolling), `YomuTextField` (IME action → next field, clear button, validation). `YomuSlider` wraps the `SliderState` slider (the plain `value` overload is deprecated in 1.5.0) while keeping the caller-owned value.
- **The Yomu signature** (`YomuSignature.kt`) — the shared vocabulary that makes every screen read as the same app; use it instead of literal shapes/colours/ad hoc surfaces: `YomuShapeTokens` (`cover`/`hero`/`tile`/`inset`/`pill` role-based corners) + `YomuBookCoverAspectRatio` (every cover, 1:1.5); `YomuCard`/`YomuCardTone` (tonal ladder Group → Raised → Hero/HeroAlt; no borders or elevation on cards); `YomuShapeBadge`/`YomuBadgeShape` (Cookie, Scallop, Sunny, Clover, Burst) and `YomuEmptyState` (the one empty/error/missing state); `YomuSectionHeader` (page-level; `YomuSettingGroup` uses it) vs the smaller in-sheet `YomuSectionLabel`; `YomuSheetHeader` (first child of every `YomuBottomSheet`; shows a close button when the sheet is a tablet dialog via `LocalYomuSheetPresentation`); `YomuNotice` (tonal strip; `Floating` replaces stock snackbars); `YomuDialog` (replaces stock `AlertDialog`; `destructive` confirm in the error role); `YomuScreenTitle` (app-bar title weight/tracking). Feature code uses `YomuTheme.space` for paddings/gaps and `MaterialTheme` roles for colour/type.
- **Shape/motion helpers** (`YomuShapeMorph.kt`): `rememberSelectionMorphShape` (MaterialShapes morph on selection) and `Modifier.yomuDecorativeShape` (hero-only decorative shapes; never behind text). `YomuMotion` transitions use the expressive scheme's spatial springs for geometry and effects springs for fades. Use `IconButtonDefaults.shapes()` / `ButtonDefaults.shapes()` on buttons for press morphing.
- Still custom by necessity: the HSV `YomuColorPicker`, the scroll indicator, EPUB canvas. Adaptive layout follows the M3 breakpoints: `YomuWidthClass` (Compact <600 / Medium / Expanded ≥840 / Large ≥1200, `margin` 16→24dp), `YomuTwoPane` (24dp margins + spacer; 50/50 at medium, fixed 360/412dp leading pane from expanded), `YomuReadableMaxWidth` (720dp default for `YomuScreenScaffold` forms/prose) vs `YomuContentMaxWidth` (1040dp for grids/dashboards). Book Details two-pane uses contained panes below the app bar (the Read/Resume button docks under the details pane instead of floating over the TOC) and reveals the bar title only once the in-pane title scrolls away; Stats splits only from expanded. The module opts into `ExperimentalMaterial3ExpressiveApi` globally (`app/build.gradle.kts`) — most M3E components are stable as of material3 1.5.0, but `LoadingIndicator` and `MaterialShapes` still need it.
- **Icons**: every app icon is `core/designsystem/icons/StackIcons` — Material Symbols Outlined at weight 300 as generated `ImageVector`s (no `material-icons-extended` dependency). `*Filled` (FILL 1, weight 400) only for the active nav item and the play/resume button; `BookmarkFilled` (FILL 1, weight 300) is the bookmark toggle's on-state. Add an icon by appending it to `tools/stack-icons/generate_stack_icons.py` and running it with `--fetch` (SVGs go to a scratch dir outside the repo).
- The design system package must not depend on `feature/*`.

- **Motion/performance rules**: no raw `tween`/`spring` in feature code — geometry uses `MaterialTheme.motionScheme` spatial specs, opacity/colour the effects specs, appear/disappear the `YomuMotion` helpers. Animated values are read in the draw/layout phase (`graphicsLayer { }`, `offset { }`, draw lambdas), not in composition, so animations hold the display's native refresh rate. `YomuBottomSheet` is an animated centred dialog (≤460dp) from 600dp width.

### Theme ↔ system bars
`MainActivity` owns the window insets controller and flips status/nav bar icon appearance on theme-mode change so bar icons stay legible. It also calls `preferNativeRefreshRate()` (`app/NativeRefreshRate.kt`) so the window requests the display's fastest mode (90/120/144 Hz) at the current resolution, re-picked on every display change while started (Samsung hides its high-rate modes during battery saver). The **reader** additionally takes over the system bars while open (`ReaderScreen`): it hides both bars for full-screen reading, colours them to the reading theme, and restores them on exit.

### Reader engine boundary
**v2 (branch `v2-native`): foliate-js is the default engine; Readium is the fallback.** The bound `ReaderEngine` is `data/reader/SwitchingReaderEngine`, which forwards to `data/reader/foliate/FoliateReaderEngine` unless `ReaderEngineChoice` (About → Diagnostics → "Use previous reading engine", device-local) picks `ReadiumReaderEngine`. The foliate side lives in the `:reader-engine` Gradle module: `reader/web/FoliateReader` hosts vendored foliate-js (MIT, EPUB-only subset in `reader-engine/src/main/assets/foliate/`, our glue in `yomu-reader.js`) in one WebView on a single local origin (book files served one at a time from the EPUB, CSP blocks book scripts, no network). Page turns are foliate's own (finger-following swipe + slide; off when system animations are). A book-like page curl that follows the finger is planned for tablets/foldables in landscape; the earlier native snapshot-slide turn and chapter stand-in were removed (see git history: `FoliatePageTurns`, `yomu-standin.js`). `FoliateReaderEngine` writes the same Readium-shaped locator JSON (href + progression, plus `locations.cfi`) and keys chapters by Readium's TOC (`ReadiumReaderEngine.publicationCache`), so positions, bookmarks and read marks work across both engines. Opening is preloaded: `warmUp()` builds a warm reader page (WebView + scripts loaded, on a `MutableContextWrapper` re-parented to the Activity when adopted) and `prepare()` reads the book ahead and loads it into that page, so a tap only places and paints the page (Resume tap → ready ~0.5 s vs Readium ~1.0–1.4 s on the emulator). The text-selection menu is the reader's own (`reader/web/SelectionMenu` wraps Chromium's ActionMode in a `WebView` subclass; the page's `yomuSelection()` gives text + CFI), and highlights draw through foliate's overlayer (`yomuSetHighlights`; taps come back as `highlight-tap`). Highlights made under foliate carry a CFI; those made under Readium carry only their quoted text (`text.before/highlight/after`), which the page finds (`findText`) when their chapter loads — and a locator without a CFI but with quoted text (Readium bookmarks/highlights, positions synced from a Readium device) is navigated to the same way, falling back to its progression. In-book search skips foliate's own (slow) search: `reader/web/SearchText` scans the raw chapter files on 4 threads in growing blocks and the page (`yomuSearch`) opens and matches only the chapters that can match, with the same folding (no case/diacritics, collapsed whitespace); hits carry the CFI and are underlined with `yomuSetSearchHits` (≤150 hits like Readium; on the 1,469-section test book a common name takes ~0.6 s, a word that isn't there ~3.3 s on the emulator). Footnote references (epub:type/role noteref, or a superscript link that isn't a back-link, as foliate's footnotes.js decides) open the note's HTML in the footnote popup instead of navigating. Scroll mode (`flow="scrolled"`, one chapter at a time): pulling on past a chapter's end or start (140 CSS px, a badge with an arrow fills once release will act) continues into the adjacent section (`continue` event; forward counts as reading through, via `ReadingPosition.expectSequentialCrossing`); scroll progress reaches 100% at a chapter's end; the page draws its own fading scrollbar (`showScrollbar`), as the chapter scrolls inside foliate's closed shadow root. Session hooks: `onForegroundResumed()` probes the page (`yomuAlive`); a page that doesn't answer within 4 s has its renderer terminated (rebuilt like a crash, at the same CFI), one that lost its chapter is sent back to it; `portableLocator()` adds the text at the top of the screen (`yomuPortable`: raw `text.before/highlight/after`) to the CFI locator so Readium can anchor on it. `:reader-engine` also holds the parked native-layout prototype (`reader/epub`, `text`, `layout`, `ui`); debug-only `prototype/*PrototypeActivity` launch either directly. The rest of this section describes the Readium engine.

The EPUB engine is Readium, but Readium types must **not** leak. All reader access goes through Yomu-owned interfaces in `core/reader` (`ReaderEngine`, `ReaderSession`, `ReaderLocator`, `ReaderTocItem`, `ReaderHighlight`, `ReaderBookmark`, `ReaderSearchResult`); only `data/reader/readium/*` imports Readium directly — `ReadiumReaderEngine` (reading), `ReadiumMetadataExtractor` (import-time metadata/cover), `ReadiumRestoreGuard` (the config-change/process-death navigator-restoration guard, installed by `MainActivity` through `ReaderEngine.installRestoreGuard(activity)`; see commit 07ac465), `PagePresentation` (render state, chapter-transition covers, reveal gating and the tap-turn queue, behind an internal `PageSurface` seam with a fake for virtual-time tests), and `RendererGoneGuard` (wraps Readium's page `WebViewClient`s to handle `onRenderProcessGone` — the system kills the WebView renderer freely in the background, and unhandled that aborts the whole app; the engine rebuilds the navigator in place instead). The Readium navigator is an `EpubNavigatorFragment`; `ReaderNavigator.host(container, fragmentManager)` owns the whole hosting transaction (also reused for renderer-kill recreation), and `feature/reader/ReaderNavigatorHost` is a thin composable around it. Reading position maths lives in the Readium-free `data/reader/ReadingPosition`. `ReaderSettings` → `EpubPreferences` mapping (scroll/paged, fontSize, theme, bg/text colour, fontFamily, lineHeight/margins/paragraph-spacing, `publisherStyles = false`) and navigation live in the engine. The engine surfaces center-taps, one `selections` stream (look up / highlight / copy / share / read aloud, with the selected text and locator), footnotes, and highlight taps via `SharedFlow`s; the selection policy (multi-word look-up → web search, clipboard, share, TTS) lives in `ReadingExperience` behind `SelectionOutlet`/`ReadAloud` ports, and the look-up-word rule is `data/dictionary/LookupTerm`, and renders highlights as Readium `Decoration`s. Reader settings resolve as a **global default (DataStore) ⊕ per-book override (Room `reader_settings`)**, written per-book-on-edit — the global default is edited on the `ReaderDefaults` screen. Five reading fonts are bundled in `app/src/main/assets/fonts/` and registered with Readium. **Preloading:** `data/reader/ReaderPreloader` (called by the Library VM ~0.8 s after the library settles, for the Resume book, and by Book Details ~0.4 s after it opens) asks the engine to `warmUp()` WebView (androidx.webkit async start-up + one idle-time throwaway WebView) and `prepare()` the book: the publication is parsed and indexed into a single-slot cache that `open()` takes over (or awaits if still loading); a newer prepare replaces it and `TRIM_MEMORY_UI_HIDDEN` releases it. Cold Resume measured 2.4 s → ~1.5 s on the emulator. The reader additionally owns reading-time tracking (writes `reading_sessions` via `StatsRepository`), TTS read-aloud, and extra-dim/brightness. See `docs/app-architecture.md` and `docs/reader-feature-spec.md`.

Reader chrome: a sleek always-or-immersive top bar (chapter title in the reading font + bookmark toggle), an optional footer (battery w/ charging, clock, chapter-weighted progress %, optional "pages left in chapter"), a floating M3E toolbar (Browse/Search/Display, coloured from the reading theme), and a single tabbed **Browse sheet** (`ReaderBrowseSheet`, `BrowseTab` = Contents/Bookmarks/Highlights/Search) plus a **More** overflow sheet — these replaced the four standalone sheets (their `*Row` helpers are reused). Settings new since bookmarks/search: `keepScreenOn`, `immersiveChrome`, `footerShow*` (incl. `footerShowPagesLeft`), surfaced via the shared `ReaderChromeToggles` (rendered in BOTH the in-reader Controls sheet and global Reading Defaults so they can't drift). Immersive mode is true edge-to-edge: while the reader is open the window uses `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES` and each EPUB page gets `viewport-fit=cover` injected (Android WebViews letterbox below the cutout otherwise; `env(safe-area-inset-*)` is 0 there). Scroll mode has a rubberband chapter-overscroll gesture (SVG arrow injected via `createElementNS`). All appearing/disappearing surfaces across the app use the shared **`core/designsystem/YomuMotion`** vocabulary — `yomuChromeEnter/Exit` (fade+scale+slide), `yomuPopupEnter/Exit`, `yomuContentSwap` (directional tab swap), `yomuChromeBlur` (API-31+ blur driven by the enter/exit transition). Child screens open from the root host with a **push** (`yomuScreenPushEnter/Exit`: the new page fades in within 150 ms on top of the old one, which stays opaque — never an empty frame); tab switches keep the fade-through slide, which a back gesture between tabs scrubs. In full-screen reading the system bars are hidden in transient mode, where Android disables the back gesture by design: the flow is tap the page (menu + bars show), then swipe back. Book Details opens with content on its first frame, seeded from what is already in memory (`LibraryCatalog.latest`, plus the last-observed read marks and reading time on a reopen), so no loading frame lands mid-transition. A back gesture begun while a page is still opening cannot be previewed (NavHost would seek a transition already running toward that page: frozen page, then a cut), so `BackPreviewFrame` takes those gestures itself and pops once the page settles. **Predictive back is enabled**: child routes pop with Material's predictive back, as in Google's apps, for gestures *and* back taps alike (`BackPreviewFrame` in `YomuNavHost` draws it; NavHost's own `predictivePop*`/`pop*` transitions just hold both pages). While dragging, the top page shrinks toward 90%, rounds its corners and drifts toward the far side, over the page underneath, which waits shrunk to 90%, offset 10% toward the swipe edge and darkened; on commit the top page keeps shrinking and fades while the page underneath glides in, grows and brightens; a cancel retraces the drag. The pose follows the finger (decelerated) and the commit is eased from wherever the pages were at release, so it feels the same at any swipe speed; a tap commits from rest. Pitfalls handled there: NavHost re-runs the pop transition lambdas on release (a gesture commit is not a tap → `gestureInFlight`), and which kind of back is running is only known during that composition, so the motion flags are read when drawing. and custom dialog surfaces (tablet `YomuBottomSheet`, `YomuDialog`, cover viewer) follow the swipe via `YomuBackPreviewHandler` + `Modifier.yomuBackPreview` (`core/designsystem/YomuBackPreview.kt`) — new dialog-like surfaces should use the same pair; see `docs/navigation-motion-plan.md`. Chapter changes reveal the new chapter with a directional rise/settle (`ReaderScreen` `revealShift`) and leave the chrome as-is (only the initial open forces it visible); paged tap-turns use Readium's animated pagination (`goForward(animated = …)`, off when system animations are disabled).

## Conventions

- Each feature follows a **Route (stateful, `hiltViewModel()`) → Screen (stateless, `On*` callbacks)** split; the `Screen` is preview-driven.
- Compose state flows down (immutable UI-state data classes), events flow up (explicitly named `On*` events). Collect ViewModel/repository flows with `collectAsStateWithLifecycle()`, and build heavy UI state (sorting, TOC models) off main with `flowOn(Dispatchers.Default)`. Keep composables stateless except for small ephemeral UI state.
- **The reader is the exception to `On*` callbacks:** every reader event is an explicitly named member of one sealed `ReaderAction` (`feature/reader/ReaderAction.kt`, e.g. `ReaderAction.OpenSearch`) raised through a single `ReaderScreen(state, onAction)`. `ReaderViewModel.onAction` runs the pure, unit-tested `reduceChrome` (menu/sheet exclusivity) and forwards book work to `ReadingExperience` via `toExperienceAction()`; `ReaderRoute` handles `Back`. Add a reader event as a new `ReaderAction`, not a new callback (leaf sheets still take named callbacks). The reading-session lifecycle (resume/pause → reading time) is owned by `ReaderRoute` (`LifecycleResumeEffect` on the destination), not the screen.
- Do not pass repositories into composables, and do not run import/database/DataStore/Readium work from composables.
- Name composables by product role, not the widget they render.
- The Book Details TOC must stay a `LazyColumn` (can be thousands of entries) **with no item key** — chapter hrefs can legitimately repeat and a keyed list would crash.
- Comment only non-obvious behavior.
- Use `@Preview` composables for design iteration; the `app/devgallery` gallery exists to validate design primitives in isolation.

## Related projects (local siblings — reference material, not dependencies)

Two other repos live next to Yomu on this machine. Neither is built or imported by Yomu, but both are high-value references — especially for Yomu's genuinely-missing features (bookmarks, in-book search). Mine them for **feature logic**, but re-implement behind Yomu's `core/reader` boundary and custom design system rather than copying verbatim.

### `C:\Users\itexp\kotlin-toolkit\test-app` — the Readium reference app (the engine Yomu sits on)
The official **Readium Kotlin Toolkit** monorepo and its demo app (`org.readium.r2.testapp`, versioned in lockstep at **3.3.0**; Yomu now targets Readium **3.4.0**, so check the 3.3→3.4 changelog when porting). It is the canonical, un-abstracted reference for the library under Yomu's reader. Style is the *opposite* of Yomu: classic **Views/Fragments/RecyclerView + Material**, hand-rolled DI (no Hilt), and Readium types used directly everywhere. Exercises the whole toolkit (EPUB / PDF via PDFium / audiobook via ExoPlayer+media3 / image-DiViNa / OPDS / LCP DRM / TTS / search / bookmarks / highlights / TOC / preferences).

Best copy-from source for **Yomu's two missing features**:
- **Bookmarks** — Room entity stores the Readium `Locator` as JSON (`locations` + `text`); spine index via `publication.readingOrder.indexOfFirstWithHref(href)`; idempotency via a unique index + `OnConflictStrategy.IGNORE`; `BookmarksFragment` lists then returns a `Locator` → `navigator.go(locator)`.
- **In-book search** — `publication.search(query)` → `SearchIterator`, paged lazily with an AndroidX Paging 3 `SearchPagingSource`; hits rendered live in-text as `Decoration.Style.Underline` via `DecorableNavigator.applyDecorations(list, group)`.
- **Highlights** (Yomu's are built, but this is the textbook version) — text-selection `ActionMode` → `SelectableNavigator.currentSelection()` → Room `Highlight` → `Decoration` (group `"highlights"`); `Decoration.extras` round-trips the DB id so `onDecorationActivated` can look the row back up for tap-to-edit.
- Also worth knowing: multi-format navigator selection by `Publication.Profile`; custom font declaration at navigator-config time (same mechanism Yomu uses); the `createDummyFactory()` process-death guard — the same navigator-restoration crash class Yomu fixed in 07ac465.
- **Caveat for porting:** the test-app reaches into Readium from its ViewModels/Fragments. A Yomu port must thread these through `core/reader` (e.g. add `search()` / `applyDecorations()` to `ReaderSession`), not import Readium in `feature/reader`.

### `C:\Users\itexp\vaachak` — sibling indie Compose EPUB reader
Another single-module native EPUB reader (`io.github.piyushdaiya.vaachak`, v2.0.1) on the **same core stack** (Compose, Hilt, Room, DataStore, Coil, Readium) but **older versions**: Kotlin 2.0.21, AGP 8.11.1, Compose BOM 2024.05, **Readium 3.1.2** (vs Yomu's 3.4.0 — APIs are not always drop-in), minSdk 30, Room v9. It ships several things Yomu lists as pending, plus features Yomu has no plans for — so it's the most useful *feature* reference, but **not** an architecture reference.

- **Built features to study:** in-book search (Readium `SearchService`), highlights + page bookmarks (unified into one Room `HighlightEntity` discriminated by a string `tag`; bookmark identity by href + `abs(progression delta) < 0.01`), flattened TOC overlay, fragment-in-Compose with a `FragmentLifecycleCallbacks` re-apply-decorations-on-resume pattern.
- **Beyond Yomu's scope:** an **AI assistant** — Google **Gemini** (`gemini-2.5-flash`) for explain / spoiler-free character ID / chapter recap / session "recall", plus **Cloudflare Workers AI** for text→image (both BYO-key in DataStore); an **offline dictionary** — embedded `dictionary.json` (~20MB) + `inflections.json` lemma map + a from-scratch `StarDictParser` (`.ifo/.idx/.dict.dz`, 32/64-bit offsets, gzip via commons-compress); **catalog acquisition** — OPDS 1.x/2.0 (`readium-opds`) + **Gutendex** (Project Gutenberg) browse + in-app download; **accessibility fonts** (OpenDyslexic, iA Writer Duospace, accessible DfA) and a first-class **E-Ink** theme mode with a contrast slider.
- **Architectural contrasts (why not to copy its structure):** stock **Material3** with a single global `isEink` boolean instead of a design system; **no Readium boundary** (Readium types leak into Compose UI + ViewModels); **no `NavHost`** — a monolithic `MainActivity` holds all navigation as Compose state; the data layer even depends on a `ui` class (`LibraryRepository` → `ui.reader.ReadiumManager`); a ~550-line god `ReaderViewModel`.
- **Do not copy (security):** `app/build.gradle.kts` hardcodes the release **keystore password in plaintext** in the signing config; user AI secrets are stored unencrypted in DataStore; OPDS offers a trust-all-TLS path. Treat vaachak as a feature blueprint only.
